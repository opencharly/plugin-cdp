# 2026.254.0539 — cdp: land screenshots through sdk.LandArtifact (G-9)

## Summary

Migrate plugin-cdp's screenshot artifact handling to the shared `sdk.LandArtifact` entry point (sdk#249, tag v0.2026254.439, plan G-8/G-9).

- `methods.go` — `runScreenshot` now lands the captured PNG through `sdk.LandArtifact(ctx, nil, "", artifact, op)` — the **host leg** (nil executor, empty venue path): cdp writes host-side directly (the capture bytes arrive over the CDP WebSocket from the host-pre-resolved endpoint; there is no venue-file pull), so LandArtifact runs the declared artifact-reality validators (`artifact_min_bytes` / `artifact_min_dimensions` / `artifact_not_uniform` / `artifact_min_cast_events` / `artifact_contains_text`) on the written file. The `os.WriteFile` stays — the host leg of LandArtifact validates only; the write is cdp's own host-side write.
- `provider.go` — the artifact-validator invocation is removed from the shared verdict pipeline: `sdk.VerbVerdict(..., false)` — no more hand-rolled validator invocation; a validator mismatch now surfaces as `runErr` → exit 1 through the same exit/stderr matcher path (identical fail semantics, single LandArtifact call).
- `go.mod` / `go.sum` — `github.com/opencharly/sdk` bumped `v0.2026248.1237` → `v0.2026254.439` (MVS floor for `LandArtifact`); the `spec` require rose `v0.2026248.1234` → `v0.2026250.2036` via `go mod tidy` purely transitively (sdk v0.2026254.439's go.mod requires spec ≥ v0.2026250.2036).
- `land_artifact_test.go` + `cdp_endpoint_test.go` — new regression coverage for the landing path (B12): `dispatch(method=screenshot)` over a REAL devtools endpoint stub (HTTP /json + WebSocket) and a REAL on-disk artifact; the failing-validator sub-test fails when the `sdk.LandArtifact` call is removed (negative-proof executed and pasted below).

No schema change, no behavioral change for non-screenshot methods.
