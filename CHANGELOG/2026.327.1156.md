# 2026.327.1156 — fix(cdp): Runtime.evaluate awaits a Promise, so an async expression's value reaches the check

## Summary

opencharly/plugin-cdp#11. A check could not read anything a page computes ASYNCHRONOUSLY: `cdp: eval` of an async IIFE answered `{}`, so the browser bed's "frames keep arriving" check (`getVideoPlaybackQuality().totalVideoFrames` sampled twice with an `await` between) could never pass — and the empty answer was indistinguishable from "the page said nothing".

- **`Runtime.evaluate` now asks for `awaitPromise`** (with `returnByValue`), so an expression that returns a Promise is awaited and its VALUE is returned.
- **The params are extracted into `evaluateParams`**, so the contract is testable without a live browser: `TestEvaluateParamsAwaitThePromise` asserts `expression`, `returnByValue` and `awaitPromise`.
- Measured where it matters: the browser bed's `browser-live-frames` step is the caller (`cdp: {method: eval, expression: "(async () => { … })()"}`); with this change the verb returns the resolved string instead of `{}`.
