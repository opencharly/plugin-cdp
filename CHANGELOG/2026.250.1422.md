# 2026.250.1422 — cdp: add the session method (plan Cutover E E-3)

## Summary

Implements **Cutover E-3** from plan/nested-capture-architecture.md: the `session` method on the `cdp:` verb — a host-side **detached CDP screencast recorder** (the `vnc: session` E-1 pattern applied to the CDP venue).

- **schema/cdp.cue** — `session` joined the `method` enum; new per-verb modifiers `action`/`fps`/`session_id`/`state_dir`/`artifact_dir`/`log_dir`/`venue`/`phase` (mirroring `#VncInput`); `params/cue_types_gen.go` regenerated by the documented `cue exp gengotypes` pipeline (package `params` + `@go(params)` wrapper + the spec schemagen yaml-retag transform — byte-identical regeneration proven on the pre-change schema, then regenerated from the modified schema).
- **session_method.go** — the provider-side dispatch: runSession (`start|stop|status`), buildSessionSpawn (this plugin's own binary in recorder mode + the `CHARLY_CDP_*` env), submission over the EXISTING InvokeProvider reverse leg — class `verb`, word `session`, `ops.OpExecute` — the same E3b channel the DevTools endpoint resolution rides. The provider spawns no process and knows no transport. Plan-step sessions fall back to `session_id: "default"` + a provider-owned temp state dir.
- **recorder.go** — the detached recorder engine: re-dials the session tab's CDP WebSocket off the host-pre-resolved DevTools base URL (the plugin's existing browser venue), `Page.enable` + `Page.startScreencast`, appends every `Page.screencastFrame` event's JPEG payload **as-is** into `<state_dir>/frames.mjpeg` (MJPEG by concatenation — no re-encode), paces the browser by acking at the session fps (fire-and-forget `Page.screencastFrameAck`, never a blocked call), and on SIGTERM/SIGINT finalizes: `Page.stopScreencast` + the deterministic `FINAL` marker + the shared `#EvidenceRow` `row.json`.
- **browser_cdp.go** — the CDP client gains a server-push **events channel** (readLoop previously DROPPED every event — `Page.screencastFrame` never reached callers) + an async `Send` for the pacing acks. Zero behavior change for `Call()` users (pre-existing tests all green).
- **cmd/serve** — hidden recorder mode (`CHARLY_CDP_RECORDER=1`) on the existing binary.
- **provider.go** — `session` dispatched before dialing (the recorder owns the wire); `cdpEnv` gains `venue` for evidence-row provenance.
- **ADE plan** — `charly.yml` gains three lifecycle checks (`cdp-session-start` → `cdp-session-status` → `cdp-session-stop`) exercising the method against a live DevTools endpoint.
- **go.mod** — sdk `v0.2026234.347` → `v0.2026248.1237`, spec `v0.2026232.520` → `v0.2026248.1234` (the session seam's `CheckContext.InvokeProvider` contract; the same pair plugin-vnc/plugin-spice consume).

A NEW test fixture proves the changed runtime path over a real wire: `cdp_endpoint_test.go` — a minimal Chrome DevTools endpoint stub (HTTP `/json` + CDP WebSocket speaking `Page.enable`/`startScreencast`/`screencastFrame` events/`stopScreencast`), and `TestRunSessionRecorderAgainstFakeEndpoint` runs the recorder end to end against it (tab resolution → dial → screencast stream → byte-identical frames.mjpeg → stop → finalize).
